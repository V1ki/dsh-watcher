# 08 · 安装部署与日常维护

> 讲清 6 个插件怎么按顺序装、Mac mini 怎么一键更新、平时怎么自检排错。

---

## 一、装之前要准备什么

这套插件套件全部用纯 TypeScript 编写，运行时只依赖 Node 24 内置能力，不用额外折腾复杂的第三方运行环境。动手前确认这 4 样东西就位即可：

- **Node.js 24**：要求 `24.9` 及以上版本。
- **pnpm**：用于安装开发依赖、编译插件、打包和跑测试。
- **DSH 主程序**：提供插件运行底座和网页侧边栏界面。
- **macOS 环境（仅微信需要）**：如果只用 GitHub 盯防和便签，Linux 或 macOS 都能完整跑起来；如果要接微信，需要一台 macOS 机器挂着微信客户端、开启系统「辅助功能」权限，并运行本地微信监听服务。

## 二、6 个插件的安装顺序

系统拆成了 6 个各司其职的插件。手动安装时，要先立好基础底座，再接上各个通道连接器与便签引擎：

| 顺序 | 模块名 | 插件包名 | 负责什么 |
|---|---|---|---|
| 1 | 性格衣柜 | `@local/dsh-persona` | 分身人设、说话风格、圈层标签与记忆 |
| 2 | Hub 总控台 | `@local/dsh-hub` | 统一收件箱、草稿箱、资料库与门口小保安 |
| 3 | Router 大脑 | `@local/dsh-router` | 智能分诊、作息通知、主人私聊与确认码 |
| 4 | GitHub 连接器 | `@local/dsh-connector-github` | 仓库轮询、Issue 与 PR 合住、评论审查 |
| 5 | 待惦记便签 | `@local/dsh-trigger-memo` | 定时轻提醒、追新闻后续与长期蹲守 |
| 6 | 微信连接器 | `@local/dsh-connector-wxarc` | 仅 macOS 可选，负责微信收发与串行模拟操作 |

在仓库根目录编好全部插件、打成压缩包并安装到 DSH，只需一组命令：

```bash
pnpm install
pnpm run build

mkdir -p dist-tgz
for pkg in dsh-persona dsh-hub dsh-router dsh-connector-github dsh-trigger-memo dsh-connector-wxarc; do
  pnpm --filter "@local/$pkg" pack --pack-destination ../../dist-tgz
done

dsh plugin --profile web add dist-tgz/*.tgz
```

- 如果不想自己记顺序，也可以使用聚合组合包 `@local/dsh-hub-bundle` 自动按依赖顺序装齐；在非 macOS 机器上会自动跳过微信连接器。
- 如果版本号没变而只是覆盖重装，建议先移除旧插件再重新安装，避免本地包缓存拦住新代码。

## 三、旧数据平滑过渡

平时升级版本或重新打包覆盖安装时，不用提心吊胆，也不用手动备份倒库：

- **历史记录自动衔接**：已有的历史消息、正在盯防的仓库与话题订阅、性格卡片、聊天偏好记忆以及审批记录，升级启动后都会自动接上继续用。
- **账号凭证安全留存**：GitHub 机器人密钥、访问令牌和本地目录配置都独立存放在用户配置目录里，重装插件不会把它们清空。
- **中途重启不重发**：如果重启那一刻恰好有消息正发到一半，开机自检会自动把它标成「待核实」，绝不会自作聪明再发一遍。

## 四、日常更新与自检

### 1. 本地改完代码的 4 条标准自检

每次改完代码或文档，在仓库根目录跑完这 4 条命令，全绿就可以放心打包：

```bash
pnpm run check:comments
pnpm run check:docs
pnpm run build
pnpm test
```

| 命令 | 查什么 |
|---|---|
| `pnpm run check:comments` | 检查所有源码与测试是否严格零注释 |
| `pnpm run check:docs` | 检查大白话文档的索引、链接、篇幅与隐私红线 |
| `pnpm run build` | 编译全部插件并拷贝前端脚本与辅助资源 |
| `pnpm test` | 运行全部单元测试与跨插件联调测试 |

### 2. 一键更新挂微信的 Mac mini

仓库自带一键部署脚本，不含任何硬编码主机地址。首次部署前，先复制一份部署模板并填好你自己的目标信息：

```bash
cp .env.deploy.example .env.deploy
```

`.env.deploy` 已被排除在版本库外，只需填写这几项：

| 配置项 | 填什么 |
|---|---|
| `DSH_DEPLOY_HOST` | 远端登录目标，例如 `user@your-host` |
| `DSH_DEPLOY_REMOTE_DIR` | 远端存放插件压缩包的目录 |
| `DSH_DEPLOY_SERVICE` | 可选，重启远端 DSH 用的系统服务名 |
| `DSH_DEPLOY_SSH_OPTS` | 可选，附加给远程登录的参数 |
| `DSH_DEPLOY_HEALTH_URL` | 可选，重启后自动探活用的本地状态地址 |

确认本地改动已经提交干净后，执行一行命令即可自动完成校验、打包、上传、覆盖重装、重启服务和探活；想先演练一遍而不改动远端，可以加上 `--dry-run` 参数：

```bash
pnpm run deploy:macmini
```

### 3. 更新完怎么确认服务在线

- **看部署结果**：终端末尾出现探活成功提示，说明远端服务已经重新拉起并能响应请求。
- **看网页侧边栏**：打开 DSH 网页界面，确认「Hub 总控台」「Router」「性格衣柜」「GitHub」「微信消息」面板都能顺利打开且显示在线。
- **微信发一句测试**：在微信私聊里给助理发一句 `列表`，如果很快收到清爽的任务汇总，说明收发链路全部正常。

### 4. 常见小排错与开发者入口

| 遇到什么现象 | 优先查哪里 |
|---|---|
| **微信发不出去** | 检查 Mac mini 是否锁屏、微信窗口是否被弹窗挡住、辅助功能权限是否开启 |
| **更新后还是旧界面** | 同版本号覆盖前确认先移除了旧插件，再刷新浏览器缓存 |
| **GitHub 没拉到新动态** | 打开侧边栏「GitHub」面板点「立即拉取」，顺手核对令牌是否过期 |
| **想查包内详细接口** | 开发者与 AI 助手请看根目录 [AGENTS.md](../AGENTS.md) 和各包下的技术契约 |

各插件的内部接口、数据表、配置参数和路由细节统一维护在对应包目录下，例如 [Hub 技术契约](../packages/dsh-hub/AGENTS.md) 与 [聚合包技术契约](../packages/dsh-hub-bundle/AGENTS.md)。
